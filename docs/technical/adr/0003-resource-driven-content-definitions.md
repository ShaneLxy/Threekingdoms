# ADR-0003：采用 Resource 驱动的内容定义

**状态**：已接受  
**日期**：2026-07-12  
**引擎基线**：Godot `4.7.stable.official.5b4e0cb0f`

## 背景

赵云、敌兵、强化、Boss 和关卡遭遇会持续增加。若将数值和规则硬编码在场景脚本中，剧情与无尽模式会复制逻辑，平衡改动也难以测试和追踪。

## 决定

- 英雄、技能、敌兵、Boss、强化、地图和遭遇使用强类型 `Resource` 定义。
- 定义资源在运行时视为只读模板；经验、冷却、强化层数、实体生命和阶段进度进入 `RunState`。
- 剧情与无尽模式复用 EnemyDefinition、SkillDefinition 与 UpgradeDefinition，只替换 Stage/Encounter 定义。
- 关键定义数据必须可在测试夹具中构造，避免测试依赖完整场景或 UI。

## 后果

### 正面

- 新武将、新兵种、新关卡主要是新增数据和有限行为实现，不复制战斗系统。
- 数值可独立审查、对比和测试。
- 局内构筑不会污染原始配置，重开一局天然干净。

### 负面

- 需要定义清晰的数据校验，避免 Resource 引用缺失或循环引用。
- 过度通用化会制造难以理解的“万能技能字段”；首版只为已设计的内容建字段。
- 资源格式变更需要版本迁移或兼容策略。

## 关联需求

TR-001、TR-002、TR-004、TR-005、TR-006、TR-007、TR-010。

## 引擎兼容性

依赖 Godot 4 `Resource` 序列化与 Inspector 编辑。项目创建后需通过最小 Resource 夹具验证导出字段、引用路径和移动端资源加载行为。
