# ADR-0001：采用混合敌军实体架构

**状态**：已接受  
**日期**：2026-07-12  
**引擎基线**：Godot `4.7.stable.official.5b4e0cb0f`

## 背景

游戏要求玩家对抗大量刀、戟、弓、盾普通兵，同时保留赵云、精英和 Boss 的精细连招、预警与表现。为所有敌军建立完整 Godot Scene、物理体、组件和逐节点更新，会增加移动端 CPU、内存、Signal 与创建/销毁压力；但将玩家和 Boss 也压缩为纯数据会损失开发效率与表现能力。

## 决定

- 赵云、Boss、精英使用组合式完整 Actor 场景。
- 普通敌军由 `EnemySimulation` 用密集运行时数据、实体 ID 和空间网格批量更新。
- 普通敌军画面使用本地对象池的 `EnemyView`；远处密集同类兵的批量渲染作为后续性能优化，不作为首日依赖。
- 碰撞、伤害与死亡以模拟层为真相；表现代理不拥有战斗状态。

## 后果

### 正面

- 兵海规模不会线性放大节点树与逐节点更新成本。
- 玩家/Boss 保留可读、可维护的组合式技能与状态机。
- 对象池和批量渲染可逐步加入，不影响战斗规则定义。

### 负面

- 需要维护模拟 ID 与表现代理绑定，调试复杂度高于“每兵一个 Scene”。
- 敌军行为必须保持简单；复杂个体行为应升级为精英或 Boss。
- MultiMesh 的像素动画、逐实例剔除和材质效果需要实际验证。

## 关联需求

TR-003、TR-005、TR-006、TR-008、TR-009。

## 引擎兼容性

使用 Godot 4.7 的 2D 节点、Resource、对象池和可选 `MultiMeshInstance2D`。仍需在目标 Android 设备验证移动端批量渲染和像素材质表现；在此之前，池化 Sprite 方案是保底实现。
