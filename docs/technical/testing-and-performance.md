# 测试与性能策略

> 状态：测试计划 v0.1  
> 关联：[Godot 技术架构](godot-architecture.md)

## 1. 原则

- 先测试纯规则，再测试小场景交互，最后进行长时间真机压测。
- 测试公共行为与设计验收标准，不断言私有变量或节点树实现细节。
- 随机三选一、遭遇和刷怪测试必须固定种子。
- 每个测试独立创建状态，结束时释放实例；不得共享 AutoLoad 污染的上一轮数据。

## 2. 测试层级

| 层级 | 目标 | 首批覆盖 |
|---|---|---|
| 单元测试 | 无场景树的纯逻辑 | 伤害/护甲、护体、经验曲线、强化抽取、刷怪预算、空间网格。 |
| 场景集成测试 | 少量节点的协作 | 赵云三段连招、击杀后经验、升级暂停恢复、Boss 阶段与护卫上限。 |
| 回归测试 | 防止数据和存档漂移 | 赵云初始定义、强化池、ProfileState 序列化版本。 |
| 性能/耐久测试 | 长时间稳定性 | 20 分钟敌军模拟、对象池回收、内存增长、帧时间尖峰。 |
| 真机手测 | 手感与热量 | 双手输入、无闪避红圈、UI 可读性、Android 温度与掉帧。 |

首选在 Godot 中接入 GUT；测试目录采用 `res://tests/unit`、`res://tests/integration`、`res://tests/performance` 和 `res://tests/fixtures`。

## 3. 必测用例

### 单元测试

- 护甲公式在 0、正值、高值时都满足最少 1 点伤害。
- “龙胆”只在第三段或主动末段同时命中至少 3 名敌军时触发。
- 同一敌人受到七探盘蛇前段伤害不超过 3 次。
- 三选一从可用池中抽取 3 个不同选项，遵守唯一/叠加上限与早期保底。
- 刷怪预算不会让同一时刻超过阶段上限；Boss 护卫不超过 4 名。
- 空间网格的线段、扇形与半径查询结果可预测且不包含失活实体。
- 弩兵单发必须使用固定直线弹道；不足三名可用弩兵或预警名额不足时，齐射必须退回单发。
- 军旗兵死亡或离开范围后，附近单位的军令增益必须立即失效；军旗兵自身不得生成伤害预警。
- 轻骑斥候冲锋必须沿水平路线连续平移，不能闪现；普通攻击与冲锋分别只接受普通攻击和主动技能拼刀。

### 集成测试

- 赵云在输入缓冲内能稳定衔接三段，超时后回到第一段。
- 普通敌军死亡后只结算一次经验、军功统计和无双能量。
- 升级选择打开时，RunDirector 暂停模拟；选择完成后恢复且不重复应用强化。
- 张郃跨越 70%/35% 时清除旧预警，只触发一次阶段转换，不超过护卫上限；雁行三刺必须先预览后逐条生效。
- 一局结算后 RunResult 正确写入 ProfileState，下一局 RunState 为全新状态。
- 旧版 Profile 升级后必须保留军功、已解锁地图、英雄、战法和当前上阵武将；迁移只能补齐缺失字段与明确的一次性版本奖励。
- 主存档 JSON 损坏时，必须从 `profile.json.bak` 恢复；恢复过程不得用损坏的主存档覆盖备份。

### 本地存档兼容

- `user://profile.json` 只保存玩家进度，不随 APK 内容更新覆盖。TapTap 覆盖安装必须保持 Android 包名与签名证书不变。
- 每个 Profile 都保存 `save_version`。每次新增字段、重命名 ID 或调整数据结构时，都增加一个只执行一次的迁移步骤；禁止以新版本默认档整体替换旧档。
- 英雄、地图、战法与章节均使用稳定字符串 ID。内容暂时下架时，旧 ID 仍保留在档案中，避免未来恢复内容时丢失玩家资产。
- 写档先写入临时文件，再替换主档；成功写入新档前保留上一份 `.bak`。卸载游戏或系统“清除数据”仍会删除纯本地存档，属于离线存档的系统限制。

### 性能与耐久

- 固定随机种子运行 20 分钟，监控存活实体、对象池大小、孤儿节点和内存趋势。
- 反复生成/回收 EnemyView、投射物、经验表现与 VFX，确认没有残留 Signal、动画、材质或绑定 ID。
- 压测期间记录平均帧时间与 1% 最差帧；关注尖峰，而不只看平均 FPS。
- 分别在“兵海”、“完整军阵”、“Boss + 护卫”和“升级弹窗前后”采样性能。

## 4. 移动端验收目标

### 设备档位

| 档位 | 参考硬件 | 系统与渲染要求 | 性能目标 |
|---|---|---|---|
| 参考档 | Snapdragon 778G / Dimensity 1080、6 GB 内存 | Android 11+、Vulkan、Godot Mobile 渲染器 | 60 FPS 目标。 |
| 最低兼容档 | Snapdragon 720G / 同等级 Vulkan 设备、4 GB 内存 | Android 10+、Vulkan、Godot Mobile 渲染器 | 30 FPS 目标。 |

逻辑画布固定为横屏 16:9、1280 × 720。实际手机若为更高或更宽屏幕，通过缩放与必要的安全边距适配；不能因为原生屏幕高分辨率而让逻辑像素美术和战斗坐标发生漂移。

| 指标 | 首次目标 | 验证方式 |
|---|---|---|
| 操作理解 | 新玩家 30 秒内能移动、手动攻击并拾取经验 | 观察测试。 |
| 操作疲劳 | 连续 3 分钟手动攻击无明显误触/疲劳反馈 | 真机试玩。 |
| 战斗时长 | 长坂坡完整一局约 10 分钟，Boss 60–80 秒 | 计时与战斗日志。 |
| 性能稳定 | 目标设备长时间战斗无持续帧时间恶化 | Godot Profiler + 真机采样。 |
| 热量 | 20 分钟无尽压测后不因热降频导致不可玩 | 目标 Android 设备手测与系统监控。 |
| 内存 | 20 分钟压测后内存曲线趋于稳定 | 性能监控、对象池计数、孤儿节点检查。 |

若设备不能稳定维持 60 FPS，优先保证输入、敌军逻辑和预警正确；画面可降级为更少表现代理、低频远处动画、减少透明 VFX 或分块批量渲染。不得通过降低敌军逻辑伤害或破坏遭遇规则来掩盖性能问题。

Compatibility 渲染器仅在最低兼容档暴露无法接受的 Vulkan 驱动问题时评估；在此之前不维护两套渲染路径。

## 5. Definition of Done

一个系统只有同时满足以下条件才可视为完成：

1. 对应游戏设计文档中的验收标准已覆盖。
2. 关键纯逻辑有单元测试；跨节点行为有至少一个集成测试。
3. 没有把局内状态塞进 AutoLoad 或让 UI 直接修改领域数据。
4. 高频路径没有逐敌军全局 Signal、每帧临时分配或无边界实例化。
5. 目标设备或同等级设备的真机检查已记录结果。
