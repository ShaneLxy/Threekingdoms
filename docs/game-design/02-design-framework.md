# 玩法设计框架

> 状态：草案 v0.1  
> 本文定义玩法模块边界，不等同于引擎代码架构。

## 核心原则

剧情模式和无尽模式必须复用同一套英雄、战斗、敌兵、掉落、升级与结算规则。两者的差异只应位于关卡导演与遭遇配置，避免维护两套战斗逻辑。

```text
游戏模式
  └─ 关卡导演
       └─ 遭遇 / 刷怪节奏
            ├─ 敌军编队与军阵
            ├─ 精英与 Boss
            └─ 剧情事件（仅剧情模式）

共用战斗系统
  ├─ 英雄：普攻、被动、主动、无双
  ├─ 敌军：兵种行为、阵型、受击与死亡
  ├─ 成长：经验、三选一强化、无双能量
  └─ 结算：军功、解锁、剧情进度
```

## 内容模块

| 模块 | 职责 | 不应承担的职责 |
|---|---|---|
| 英雄 | 兵器、普攻、被动、主动、无双及专属强化 | 直接决定关卡刷怪节奏。 |
| 敌兵 | 单位行为、攻击方式、弱点与视觉识别 | 承担剧情文本或永久数值成长。 |
| 军阵 | 由多种敌兵组成的战术压力与破解方式 | 替代单个敌兵的基础行为。 |
| 关卡导演 | 时间线、刷怪预算、事件、敌将出场与胜负条件 | 改写英雄或敌兵的基础规则。 |
| 局内强化 | 让本局构筑产生分支 | 提供永久养成。 |
| 局外成长 | 解锁和轻量长期进度 | 压倒局内随机构筑。 |

## 关卡导演的两种实现语义

| 模式 | 关卡导演输入 | 产出 |
|---|---|---|
| 剧情模式 | 剧情时间线、预设遭遇、事件节点、Boss | 有叙事节奏的固定难度曲线。 |
| 无尽模式 | 时间、难度曲线、刷怪预算、敌军权重 | 持续增长的随机敌军组合。 |

## 内容数据层级

后续每个可配置内容都应归属于以下层级之一：

1. **定义数据**：英雄、敌兵、技能、强化、地图、Boss 的基础定义。
2. **遭遇数据**：某一分钟出现什么兵种、如何成阵、数量压力为何。
3. **运行时状态**：本局等级、已选强化、当前生命、敌军存活状态、事件进度。
4. **结算数据**：军功、解锁、章节完成度、统计信息。

定义数据不应被运行时状态直接污染；例如“赵云技能定义”与“本局赵云已升级的技能等级”应分开管理。

## 设计约束

- 普通兵必须可用批量逻辑与表现代理承载；只有玩家、Boss、精英等少数单位使用完整高成本表现。
- 敌军压力优先通过兵种组合、进攻方向和军阵创造，而不是无上限堆叠独立单位。
- 新增武将应复用“普攻 + 被动 + 主动 + 无双 + 专属强化”的内容结构。
- 新增关卡应配置遭遇与事件，不应复制一套新的基础战斗规则。

## 待验证决策

- 20 分钟无尽模式结束时，是进入最终 Boss 结算，还是允许继续挑战。
- 局外天赋的强度上限，避免养成压制操作与局内构筑。
- 武将是否允许额外携带通用兵法/副技能；首个版本不加入。
